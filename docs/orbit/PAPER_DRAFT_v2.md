## 摘要

自进化，指智能体用自己做事的经历来改进自己：任务做完、复盘得失、把教训固化成能力。最新一批能修改自身代码的系统（全量脚手架路线）已经证明"智能体**能**改自己的代码"，但这样的循环能不能**一直转下去**，取决于一个此前没被正面回答的问题：**进化算子是否完整**。现有系统普遍有三个毛病：**反馈黑箱**——只知道改完"行不行"，不知道"错在哪一步"；**方向盲目**——不知道该往哪改，也没有分工；**历史流失**——这次验证有效的改进，下个会话就忘了。三者可以归结为一句话：算子集合是残缺的。为此我们提出 **LEAP**（Long-term Evolution with Attribution and Propagation），把自进化组织成一条**五个算子的完整流水线**：**表达**（路由：这次任务该用哪些资产）、**归因**（复盘：哪一步立功、哪一步拖后腿）、**定向变异**（多智能体分工、真实修改代码）、**选择**（考试：裁判分支暂存 + 四级评审，通过才并入主线）、**遗传**（存档：代码提交 + 带版本谱系的技能）；**重要性记忆**是全程记录的账本。我们在自进化编码智能体 **Ouroboros**[4] 之上实现 LEAP，构建 130 条成功任务语料，用四臂消融实验在进化期检验归因与遗传算子的必要性，用 Terminal-Bench 89 项任务 pass@5 主验收整体收益（890 次独立评测），并用技能部署前后测直接度量传承收益。实验表明：去掉归因，进化退化为重复试错；去掉遗传，改进无法积累——五个算子缺一不可，**算子完整正是这类系统从"能走几步"到"持续运转"的分界线**。

## 1 引言

### 1.1 背景：从"能改"到"可持续进化"

一个大模型智能体由两部分组成：**模型**（θ，参数固定不动）和**脚手架**（Σ，模型之外的一切——提示词、记忆、工具、乃至代码本身）。自进化就是**不改模型、只改脚手架**，让系统越用越强。

按"改多少"由轻到重分四档：改提示词 → 改记忆 → 改工具/技能 → **改整个程序**（全量脚手架更新）。最后一档最彻底：智能体读自己的源码、给自己打补丁，补丁通过测试才能生效——相当于一个会修改自己源码的程序员。因为"改代码的人"本身就是被改的程序，这条路被普遍认为最接近**递归自改进**，也是当前最活跃的研究前沿。

但本文追问一个更根本的问题：**能改代码 ≠ 改得好**。这样的自我修改循环，怎样才能一直转下去、越转越好？（详见第 2 章）

实践中，转不下去的循环长这样：预算反复烧在相似的无效改写上，同一类失败换个面目一次次重现，而会话一结束，系统对"自己试过什么、为什么失败"的记忆清零——它不是不能改，而是**改完就忘、败了不知为何、下一轮从零开始**。

### 1.2 进化循环的三个结构性缺口

把现有系统放在一起看，它们的困境可以归纳为进化循环的**三个结构性缺口**：

1. **反馈黑箱——只知道"行/不行"，不知道"错在哪一步"。** 现有系统大多把整条任务轨迹或一个分数当作改进信号：STOP 按效用分择优、DGM 按基准分留档案——它们看得到"这版更好"，看不到"哪一步坏了"。就像学生刷题只对答案、从不检查哪一步算错——下次还在同一个地方跌倒。

2. **方向盲目——不知道往哪改，也没有分工。** 候选改进由单个智能体沿单一路径反复试错产生：不分析任务形态，不借鉴历史经验，规划、调研、写代码、验证全混在一起（DGM 用档案维持了多样性，但单条路径内部仍是一个智能体一气呵成）。在"改提示/改工具/改技能/改流程"这么大的空间里乱试，预算大量浪费在无效方向上。

3. **历史流失——这次学会了，下次全忘。** 即使某次改进被验证有效，它的经验也随会话结束而消失。既有系统并非全无记录——档案树存的是"**谁分数高**"的成绩单，不是"**为何成败、败在哪一步**"的病历；更关键的是，"如何把一类任务做好"这种**行为级能力**连载体都没有：没有技能库，就没有基因库，每一代都从同一份代码冷启动。

三个缺口会互相加强：不知道错在哪（黑箱）→ 只能乱改（盲目）→ 改错了也没记录（流失）→ 下次接着乱改。**这就是既有循环"能走几步却不可持续"的根源。** 第 3.1 节会把这三个毛病归结成一句更狠的诊断：**进化算子集合是残缺的**。

### 1.3 本文方案：算子完整的进化流水线

LEAP 的答案：把自进化组织成一条**算子完整的流水线**，每个算子管一段，首尾相接：

- **表达（路由）**：新任务来了，先"分诊"——判断任务类型，决定开哪些工具、推荐哪些技能、套哪套执行策略；
- **归因（复盘）**：任务做完，逐步骤打分——哪步立功（关键步骤）、哪步拖后腿（拖累步骤）；**连"进化本身"也被复盘**；
- **定向变异（实施）**：依据复盘证据，多智能体分工（分析→调研→改码→验证），在隔离克隆里真实修改代码；
- **选择（考试）**：改动先放在"裁判分支"上，过四道评审闸门才并入主线；没过就回滚、记账；
- **遗传（存档）**：通过的改进以两种形式固化——**代码提交**（进主线，可回滚；改"能做什么"）和**技能**（带版本谱系 v1→v2，跨会话复用；存"怎么做好"）。

**重要性记忆**是贯穿全程的账本：证据、决策、结果、技能全部按重要性记录与检索。

关于命名：LEAP = Long-term Evolution with Attribution and Propagation。Long-term 指记忆维系的跨会话连续性，Evolution 指整条流水线，Attribution 指复盘归因，Propagation 指技能与提交的跨代传承；合起来也是"跃迁"——每一代被验证的改进都固化下来，能力是阶梯式上涨的。

**实现底座先交代清楚**：Ouroboros 本身的进化只有"评审后提交"这一招（可靠，但单点）；表达（路由）这个算子和记忆（重要性账本）这块基底，是我们在它之上用成熟技术做的**工程适配**，不算新发明；真正的新东西是贡献里"机制"条的三项设计——它们管其余四个算子（战役一个机制实现变异和选择两个算子）。

**本文贡献（三点）**：

- **框架**：提出 LEAP——以重要性记忆为基底、由表达、归因、定向变异、选择与遗传五个算子构成的自进化循环，并给出任一算子或基底缺位时循环的退化形态（表 3-1）。
- **机制**：为其余四个算子（归因、定向变异、选择、遗传）给出三项机制设计，分别堵住三个缺口——双轨归因（任务轨 + 幂等的进化循环轨，连进化自己的成败也能复盘）、证据引导的多角色战役（**一个机制管两个算子**：定向变异＝隔离克隆里分工真改代码，选择＝四道闸门＋补丁可回滚）、两种基因型的遗传（吸收提交 + 带版本谱系的技能）。
- **实证**：一套可复用的进化评测体系——130 条带完整溯源、可离线回放的进化语料，四臂算子消融设计与技能部署前后测口径，Terminal-Bench（89 项 × pass@5，890 次独立评测）跨域主验收，全部证据可审计。

## 2 相关工作

### 2.1 组件级脚手架改进：提示、记忆与工具

先看"只改一个零件"的三类方法（背景，非本文重点）：

- **提示优化**：不改模型，反复打磨提示词。按反馈信号分四派——看分数（标量）、看批评（定性，如 Self-Refine、Reflexion）、当基因养（种群式，如 EvoPrompt、Promptbreeder、GEPA、DEEVO）、模拟梯度（文本梯度）。证明了"用语言迭代修改"可行，但只改提示文本，且多是单优化器单路径。
- **记忆与长期学习**：把经验存下来反复用（Generative Agents、MemoryBank、ExpeL、Mem0、A-MEM、FORGE）。核心两难：存太多检索噪声大，存太少长期能力差。本文记忆按**重要性**取舍，且存的不仅是任务经验，还有"进化本身的历史"。
- **工具与技能**：给智能体扩展行动空间——动态选工具（路由）、边用边磨（Voyager）、自己造工具（SkillWeaver、PyVision 等）。本文同样用技能，但加了三个属性：**可遗传**（哈希+版本谱系）、**可审查**（不审查不能跑）、**可进化**（按真实使用数据变异）。

这三类各自证明"一个零件可以持续改进"，但零件之间不协同、方向没人定、成果不沉淀——这正是"改整个程序"路线（下节）的出发点。

### 2.2 全量脚手架更新：改自己源码的自进化智能体（重点）

这是本文所在层级：智能体把**自己的代码**当修改对象。两个标志：**自指**（改代码的改进器就内嵌在被改的程序里，随迭代一起进化）与**验证器门控**（补丁通过测试/审查才生效，失败回退）。思想源头可追溯到自改进程序的早期探索[21,22]；现有系统全部落在"有界、可验证"的工程形态内。按组织方式分五条线：

1. **递归自改进的程序化实现**：STOP 最早把脚手架抽象成"改进器"，反复生成候选、择优输出；Gödel Agent 用运行时打补丁把自审—自改—递归推到极致。
2. **开放式进化与谱系档案**：Darwin Gödel Machine 维护一棵不断生长的智能体档案树，多路径并行探索；Huxley–Gödel Machine 用"谱系级元生产率"引导进化方向。
3. **运行时实时自改写**：Live-SWE-Agent 第一个在真实软件任务执行中即时改写自己的脚手架。
4. **面向科学发现的程序进化**：AlphaEvolve 用进化范式持续接收评估器反馈做科学发现；ShinkaEvolve 用极少评估次数做开放式程序发现。
5. **设计空间搜索与联合符号更新**：ADAS 把"智能体设计"当搜索空间；GPTSwarm 把智能体建模成可优化的图；Agent Symbolic Learning 用自然语言梯度联合更新提示/工具/流水线。

其中与本文关系最近的是 **Ouroboros**[4]：它以"受评审的核心进化"把编码智能体的自改进约束在评审链与可回滚提交上。**LEAP 以 Ouroboros 为实例基底**，并把这类单点评审机制扩展为下文的完整算子循环。

**这些系统共同的三个缺口**（与 1.2 对应）：反馈黑箱（评估分数直接驱动下一轮，不定位失败步骤）；方向盲目（就算 DGM 用档案维持多样性，单条路径内每次更新仍是一个智能体一气呵成，没有分工）；历史流失（候选、成败、版本沿革没有结构化账本）。LEAP 的机制设计逐项针对这三个缺口。

### 2.3 小结

组件级方法各自证明"一个零件能改"，全量脚手架系统证明"整个程序能改"——但"往哪改、改得对不对、改完怎么传承"这个完整问题没被回答。LEAP 用归因回答第一个，用选择回答第二个，用遗传+记忆回答第三个；以 Ouroboros 为基质层，把它的单点评审循环升级为带方向、带归因、带传承的持续循环。

## 3 方法：LEAP 进化框架

### 3.1 总览：五个算子 + 一个账本

**💡 白话版**：把 LEAP 想成一条流水线。每个任务走一遍——

**为什么偏偏是这五个算子？** 既有系统改的是一个**种群规模为 1** 的特殊种群：没有多余的个体可以牺牲，主线一坏就无路可退；没有基因库可以继承，每一代都从同一份代码冷启动。所以决定它能不能持续进化的不是种群规模，而是**算子齐不齐**。对照进化需要的最低配置逐项清点：产生候选（变异）✓ 有雏形、淘汰候选（选择）✓ 有雏形；**适应度证据（归因）✗ 缺**、**跨代存续（遗传）✗ 缺**、**资产被调用的通路（表达）✗ 缺**——而且既有系统从来没有可遗传的资产，所以连"缺表达"都没暴露出来；遗传和表达必须成对补齐。

```
表达(分诊) → 执行任务 → 归因(复盘打分) → [每N条触发一次]
    → 定向变异(分工真改代码) → 选择(裁判分支+四道闸门考试)
    → 遗传(提交存档 + 技能存档) → 全程记账(重要性记忆) → 下一个任务
```

形式化：智能体状态 A_t = (θ, Σ_t)，θ 是固定的模型参数（本文不动模型），Σ_t 是可进化的脚手架。每个任务完成后依次执行：

- **表达（Expression）**：`(信封, TopK技能, 策略) ← Express(t, M, S)`——路由决定哪些遗传资产在本次任务被调用（第 3.2 节）；
- **归因（Attribution）**：`E ← Attribute(τ, H)`——从任务轨迹和战役账本 H 里算出每一步的信用，形成"该强化什么、该淘汰什么"的证据（第 3.3 节）；
- **定向变异（Directed Variation）**：`Δ ← Variation(E, M)`——证据引导下，多角色智能体分工产生真实代码补丁（第 3.4 节）；
- **选择（Selection）**：补丁先放裁判分支，过四级评审才并入主线；失败回滚并记账（第 3.4 节）；
- **遗传（Heredity）**：通过的改进两种存档——**代码提交**（进主线）与**技能**（带版本谱系）（第 3.5 节）。

**算法 1（单条语料记录上的完整循环）**

```
输入: 任务 t; 脚手架 Σ; 记忆 M; 战役账本 H; 技能种群 S
 1: (信封, TopK, 策略) ← Express(t, M, S)         ▷ 分诊
 2: τ ← Execute(t; 信封, TopK, 策略)              ▷ 执行
 3: E ← Attribute(τ, H)                           ▷ 复盘打分
 4: M ← MemWrite(M, E)
 5: if PromoteDue(every-N) and Worthwhile(E):     ▷ 每 N 条判断一次要不要进化
 6:     plan ← Plan(E, H)                         ▷ 分工规划
 7:     Δ    ← Implement(plan; 隔离克隆)          ▷ 真实改代码
 8:     if Preflight(Δ) and ReviewChain(hash(Δ)): ▷ 四道闸门
 9:         Absorb(Δ → H, Σ)                      ▷ 过了：提交存档
10:     else: Record(H; abandoned / no_op)        ▷ 没过：记账回滚
11: S ← SkillEvolve(τ, Stats(S))                  ▷ 技能生成/变异/审查
12: M ← MemWrite(M, Δ, S, 结果)                   ▷ 记账
```

**表 3-1：算子完整性——每个算子缺了会怎样**（这也是第 4 章消融设计的依据）

| 缺位算子 | 循环退化成什么样 | 对应第 2.2 节缺口 |
|---|---|---|
| 归因 | 不知道错在哪，只能乱改 | 反馈黑箱 |
| 定向变异（分工） | 退回单智能体单路径瞎试 | 方向盲目 |
| 选择 | 没考试就上线，坏代码污染主线 | —（有界进化的安全底线） |
| 遗传 | 学会的下个会话全忘 | 历史流失 |
| 表达 | 存档的能力没人调用，白存 | —（没遗传资产时暴露不出来的隐性缺口） |
| 记忆 | 账本没了，一切从头再来 | 历史流失 |

> 三个缺口 ≠ 五个算子的一一对应：方向盲目靠归因（给证据）+ 表达/变异（给引导和分工）一起修，历史流失靠遗传 + 记忆一起修——第 4 章的消融因此选拆归因和遗传这两个"证据源头"。
>
> 另外表 3-1 有六个名字，但**算子只有五个**：记忆是基底（全程账本），不是第六个算子——算子动手干活，记忆负责记录；不过它一坏循环照样断，所以一并列入。3.4 节把变异和选择合在一节讲，是因为流水线首尾相接，不代表它们是一个算子。

> **【图 3-1】**（已生成：`figures/fig3_1_framework.png`）三面板布局：① 右侧大面板 = 进化循环（五算子卡＋数据流箭头）；② 底部紫色面板 = 技能遗传管线（轨迹经验→生成→变异→审查→前后测，顶部绿条 = 重要性记忆账本）；③ 左侧绿色面板 = 选择门控（裁判分支 + 四级闸门 + ✓吸收/×回滚）。

### 3.2 表达：智能路由（任务的分诊台）

**💡 白话版**：新任务进来，先由一个纯规则的"分诊台"判断——这是什么类型的任务？然后一次性决定三件事：开哪些工具（信封）、推荐哪些技能（Top-K）、套哪套执行策略（分支）。判断不准就什么都不过（中性兜底），"不确定就不乱给方向"。

分类是一条**信号优先级链**：先看任务类型提示 → 再看工作区事实（有工作区就是编码类）→ 再看记忆模式 → 最后扫中英文关键词；四级全落空 = (simple, 无信号)。零 LLM 成本、确定性可复现。

**工具信封**——本次任务能看到哪些工具：

$$T_{\mathrm{env}}(t) = \big(\mathrm{ToolSets}[y] \cap A_{\mathrm{unfiltered}}\big) \setminus \mathrm{Avoid}(b) \;\cup\; T_{\mathrm{ctrl}}$$

**💡 白话版**：每种任务类型有一套预设工具包，和当前实际可用的取交集，再减去分支明确不要的，加上控制面工具（永远保留）。三条安全线：判定永远基于"未过滤全集"（防止越过滤越窄）；被隐藏的工具随时能重新打开、也能被列出来（模型知道还有什么可开）；**路由只收窄初始视野，从不删除能力**。

**技能推荐**——每个技能打分：

$$\mathrm{score}(s,t) = \min\{1,\; 0.5 + 0.3\,\mathbb{1}[\text{标签命中}] + 0.2\,\mathbb{1}[\text{名称命中}] + 0.1 \min(2, n_{\text{文本}})\}$$

**💡 白话版**：底分 0.5；标签命中 +0.3、名字命中 +0.2、描述文本命中每处 +0.1（最多两处）；低于 **0.6** 不推荐——0.6 恰好等于"至少沾一个字段"。分支还能加分（boost）/减分（demote）：**减分是压倒性的**——相关性分在加减分**之前**先封顶 1.0，被否决的技能减 0.5 后最多剩 0.5，够不到 0.6 的门槛，哪怕它全字段命中也必出局；唯一例外是被 always 显式钉住。分支说"不要"，就不会被高相关性翻案。

**分支适配**：分类命中的分支会追加正向执行策略和反模式（"禁止xx"），过滤/排序/截断记忆注入——全部是**追加，不替换**；分支配置坏了就自动退回无调整。分支成熟度分五级（L0 空配置 → L1 通用礼仪 → L2 方向级策略〔当前〕→ L3 用轨迹统计自动生成配置 → L4 结果回填自动调优）；路由决策全程落盘，为 L3/L4 校准供数据。

> **【图 3-2 占位】** "一次分类、两个消费者"结构图：顶部信号优先级链；左下横向路由（信封+技能评分+三重逃生通道）；右下纵向适配（四层分支调整+main 兜底）；底部"路由历史→回填校准"虚线回路。

### 3.3 归因：给每一步打分（复盘）

**💡 白话版**：每件事做完都写复盘。有两条复盘线——**A 轨复盘"任务"**（这次任务哪步立功哪步拖后腿），**B 轨复盘"进化本身"**（上次改进战役，是分析没做好还是验证没做好）。打分规则很直白：成功 +0.2、出错 −0.3（罚比奖重，保证坏步骤沉底）、又快又省再 +0.1。

**A 轨（任务复盘）**：任务完成即刻触发。从工具调用日志重建步骤序列（报错或超时算错误步），每步打分：

$$c_i = 0.5 + 0.2\,\mathbb{1}[\mathrm{ok}_i] - 0.3\,\mathbb{1}[\mathrm{err}_i] + 0.1\,\mathbb{1}[\mathrm{fast}_i] + 0.1\,\mathbb{1}[\mathrm{lean}_i]$$

归一化后排序：**关键步骤** = Top-3（成功模式），**拖累步骤** = Bottom-2（失败模式）——这两组就是后面技能生成的原料。再用一个轻量 LLM 调用提炼整体经验（目标类型、复杂度、成功因素、失败因素、可复用模式），连同逐步骤明细一起落盘。

**B 轨（进化复盘）**：上次改进战役自己也会留轨迹。用**单调游标**扫描战役账本——每条已出结果（吸收/放弃/无操作）且没消费过的检查点，重建"那次进化自己的步骤"，用同一套打分；LLM 提问换成"这次进化的分析/构建/验证各阶段哪里成了、哪里败了"。游标写回，**保证每条轨迹恰好被消费一次**（幂等）。首轮进化前 B 轨是空的——从第二次复盘起，"进化失败在哪一环"就有据可查。**这是 LEAP 区别于既有系统的关键：不只复盘任务，还复盘进化自己。**

**策略摘要（不花 LLM 预算）**：进化决策前，按改进目标检索同类历史经验（吸收者优先、取前 5 条），拼成摘要——策略档位（standard/optimized）、成功/失败模式、推荐工具（关键步骤工具计数 Top-5）、置信度（同类中吸收占比）——注入决策上下文。

### 3.4 定向变异与选择：真改代码 + 四道闸门

**💡 白话版**：这一节讲**两个算子**——定向变异（真改代码）和选择（四道闸门考试），它们在流水线上首尾相接，所以合在一节讲。每吃进 N 条语料，判断一次"值不值得进化一轮"。决定改之后，四个角色分工——分析员拆目标定验收标准、调研员查资料、构建员真改代码（在隔离克隆里）、验证员把关。改出来的补丁**先放在"裁判分支"上**（主线暂时看不到），然后过四道闸门：预审 → 范围检查 → 测试 → 终审；全过才并入主线，没过就回滚记账。**任何一次拦截都会记一笔"债"，债没还清之前暂停后续吸收**——防止带病上线。

**方向与触发**：持久化计数器每消费 N 条记录归零一次，形成一次"是否发起战役"的判断（逐任务进化太贵太吵，every-N 把注意力聚拢成批）。进化决策器拿着归因摘要（3.3）和战役账本产生候选目标；任务形态上下文来自 3.2 的分类。

**分工实施（变异算子）**：规划器产出结构化计划——**分析者**拆解目标、**调研者**收集事实、**构建者**最小改动实施、**验证者**构建+测试把关；多个候选可并行进战役队列，隔离服务器逐一真实执行。与"一次性自我改写"不同，每次实施都在隔离环境，产物以提交为单位可回滚、可追溯、可统计。

**验证吸收（选择算子）**：两步——先**暂存**（补丁提交在裁判分支上，主线不接触），再**门控**：

$$\Sigma_{t+1} = \begin{cases} \Sigma_t \oplus \Delta_t, & \text{若 } \mathrm{Pre}(\Delta_t) \wedge \mathrm{Scope}(\Delta_t) \wedge \mathrm{Preflight}(\Delta_t) \wedge \mathrm{Review}(h(\Delta_t)) = 1 \\ \Sigma_t, & \text{否则} \end{cases}$$

**💡 白话版**：四道闸门依次是——**建议预审**（先粗筛掉明显不行的）、**作用域评审**（只许改目标声明范围内的文件和主题，不许越权）、**测试预检**（构建+回归必须先过）、**终审**（审查结论和补丁哈希绑定，改一个字结论就作废——杜绝"审的是 A、合的是 B"）。整条闸门链是**保守语义（fail-closed）**：任何一道的结论缺失、过期或拿不准，一律按"不通过"处理——**进化的默认值是"不吸收"**。任何一道没过，除了否决本次，还记一笔**就绪债务**，债没清前暂停吸收。结果三态记账：**吸收**（并入主线）/ **放弃**（目标被否）/ **无操作**（没改出有效东西），全部进战役账本；失败候选自动回滚，并作为证据回流 3.3 的 B 轨。

> **【图 3-3 占位】** 泳道图：方向选择与触发 → 四角色泳道（隔离克隆）→ 裁判分支暂存 → 四级闸门 → 三态出口；底部失败回流虚线。

### 3.5 遗传：技能种群（把学会的存下来）

**💡 白话版**：代码改进用提交存档（3.4），**能力**用技能存档。技能 = 一个可独立执行、带版本号的能力包。它的一生：轨迹达标 → 生成（待审查）→ 审查通过才能跑 → 被真实使用 ≥10 次且成功率 <80% → 触发"重写"（必须针对真实失败）→ 新版本过小测验和审查 → v2 上线；不通过自动回滚到 v1 且立即可用。收益用"同一批任务的前后测差值 Δ"直接度量。**技能算记忆吗？** 算存储、不算账本——记忆只记录、被查阅，本身不改行为；技能会被真实执行、按用得好不好被淘汰重写。记忆让循环连续，技能让能力传承。

**(i) 生成**：轨迹入选当且仅当

$$|T_\tau| \ge 8 \;\wedge\; \mathrm{Repair}(\tau) \;\wedge\; \mathrm{Success}(\tau)$$

（工具调用 ≥8 次〔按语料中位数校准〕+ 出过错但恢复了 + 任务成功）。从关键步骤（Top-3 / Bottom-2，见 3.3）提炼技能包，附来源标记与内容哈希。生成即进入"待审查"——**没审查（或没持有人背书）的技能不能执行**。

**(ii) 变异**：技能账本统计每个技能的真实执行次数 n_s 和成功率 r_s；进入变异候选当且仅当

$$n_s \ge 10 \;\wedge\; r_s < 0.8$$

——"被用过且不够好"。重写时把该技能**最近的真实失败文本**直接塞进提示，要求新版本必须消除这些失败；候选池有界（原版+新版+兜底池），指纹去重防近亲繁殖。新版在 ≤5 条案例的迷你评估集上打分：

$$F(\tilde s) = \frac{|\{x \in D_s : \mathrm{pass}(x)\}|}{|D_s|}$$

门槛带**校准折扣**：如果历史显示"评估分总是比实测高"，准入门槛自动上调（θ_F ← θ_F + max(0, λ·d)，d 是评估与实测之差的滑动平均）——防止评估器漂移放水。

**(iii) 选择与版本演进**：新版哈希绑定审查结论，过了才覆盖旧版；没过自动从备份恢复旧版并恢复其可执行状态（**回滚后立即可用**）；回滚后进入冷却期防止反复折腾。通过者版本号 +1，连同成功率、适应度一并记录——技能由此有**谱系**。

**(iv) 收益兑现**：新技能经 3.2 的路由 Top-K 回到任务执行；真实收益 = 部署环境同任务集前后测之差 Δ = r_post − r_baseline（第 4.3 节）。变异被拒/回滚也如实记录。**"任务 → 技能 → 任务"正反馈**就是 Propagation 的微观机制。

> **【图 3-4 占位】** 技能生命周期状态机：轨迹→（三门槛）→待审查→（审查）→可执行→（n≥10 且 r<0.8）→变异候选→（小测验+审查）→v_{k+1} 或回滚；每条转移标注对应观测文件。

### 3.6 基底：重要性记忆（全程账本）

**💡 白话版**：流水线上所有的东西——复盘证据、决策、提交、技能版本——都写进同一个笔记本。每条记录算一个**重要性分**（规则打分为主，拿不准才用模型仲裁）；空间不够时**删最不重要的**，不删最早的；"发现关键缺陷"这种短但值钱的记录不会被长度惩罚误删。检索按标签+重要性双重过滤。

三个算子都靠它：表达读技能画像做推荐、按分支配置裁剪记忆注入；归因读历史证据校准打分；定向变异读战役账本定方向。没有这个账本，每次循环都是冷启动——这就是 LEAP 名字里 **Long-term** 的含义：进化不是一次性改写，每一轮结束都是下一轮的起点。

## 4 实验

第 4 章回答三个递进的问题：**(1) 循环转起来了吗**——装上五算子后，能否在真实语料上持续产出可审计的进化产物（4.1–4.3）；**(2) 收益迁移得了吗**——进化后的智能体在从没见过的任务域上有没有整体提升（4.4）；**(3) 缺口修复真的来自对应算子吗**——拆掉归因和遗传，循环是否如表 3-1 预言的那样退化（4.5）。4.6 用机制案例和产物画像给出定性直证。所有指标来自自动落盘的可审计文件，判定口径提前给出，负结果如实报告。

### 4.1 进化语料：从哪来、怎么筛

**(1) 真实执行**：从 GAIA 验证集[30] 出发，以基础实例（一个自进化智能体，见 1.3）在受控服务器环境**一次性连续执行全部 165 个验证任务**；每条记录带完整任务结果、逐步骤工具调用轨迹（参数/结果摘要/错误标记/全量观测）与运行清单。

**(2) 一次性提纯**：按任务去重，每任务保留最新已评分实例（正确 > 错误 > 未评；同级取最新），带完整溯源。结果：165 条唯一任务 = **130 正确 + 35 错误**；难度分布 L1 53 / L2 86 / L3 26。

**(3) 为什么只用 130 条正确的**：技能生成门槛要求"成功 + 自我修复"，错误任务进不了生成路径；但失败信号没丢——正确任务的轨迹里本来就有"出错→修复"，错误步被归因完整保留，成为变异和决策的失败素材。130 条以**离线回放**喂入：任务不重跑、零执行成本，进化产物（提交/技能/经验）全部由回放驱动的反思与战役真实产生。

**(4) 公平性**：评估基准 Terminal-Bench[31] 与 GAIA 不同源不同题面，零重叠；评测在全新环境，记忆技能不迁移，只有代码级产物生效——迁移收益和任务层即时能力严格分开。

### 4.2 四臂怎么切：围绕"算子缺了会怎样"

第 3 章的主张是"算子完整才可持续"（表 3-1）。四臂直接检验这句话：V0 和 V3 是两个端点，V1/V2 各拆掉一个算子。

**表 4-1：四臂定义**

| 臂 | 配置 | 检验什么 |
|---|---|---|
| V0（基线） | 全关 | — |
| **V1（−归因）** | A/B 双轨复盘和策略摘要停用；其余全开 | 表 3-1 第一行：没复盘 → 乱改 |
| **V2（−遗传）** | 技能生成/变异/部署全链停用（路由无技能可推）；代码提交保留；其余全开 | 表 3-1 第四行：没传承 → 不积累 |
| V3（全算子） | 全开 | — |

**为什么只拆这两个**：① 它们对应 2.2 的两个缺口（黑箱/流失），拆掉即检验核心主张；② 方向盲目由归因和表达/变异**共同**修复（3.1），拆掉归因后证据消失，V1 因此同时覆盖两个缺口的退化路径；③ 选择不能拆（不考试就上线=不安全），改用三态记账率和闸门拦截分布刻画；④ 变异不能单独拆（没变异=没候选=和 V0 重合）；⑤ 表达/记忆是常开基底，单拆会切断进化层的输入输出——其价值由 V3−V0 整体差值和过程观测（表 4-2 第四行）覆盖。

**在哪里测**：消融的检验场是**进化期**——被拆的算子产物（经验、技能）本来就不迁移到评测环境，在 Terminal 上与 V3 没有可测差异。所以：进化期四臂全跑（4.3/4.5）；**Terminal 只跑 V0 vs V3**（89 项 × pass@5，每臂 445 次，共 890 次，4.4）。

**公平性**：同语料、同顺序、同模板（统一模型槽位、同预算、同 every-N）；每臂独立隔离会话；支持断点续跑；V0/V3 差距明显时补 1 次重复排除噪声。

**表 4-2：主张—证据映射**（全部来自自动落盘的可审计文件）

| 板块 | 要证明什么 | 核心指标 | 支撑指标 | 数据来源 |
|---|---|---|---|---|
| 多智能体战役（变异+选择） | 有归因的战役比没归因（V1）更高产、更省 | 吸收率 = absorbed/战役总数（V3 vs V1） | 每吸收成本；通用层变更占比；三态分布；评审链各闸门通过/拦截分布 | 进化账本+会话账本 |
| 经验归因 | 历史经验真的参与并改善决策 | 决策时经验摘要注入率；目标重复率（消融核心） | **信用分离度核查**（错误步骤 vs 成功步骤的平均信用差——验证打分公式真让失败沉底）；经验累积与吸收率相关 | 经验账本+决策记录+轨迹 |
| 技能遗传 | 变异让技能在同类任务上实测变好 | 部署前后测差 Δ | 技能生成率；变异接受/回滚事件；谱系深度 | 技能统计/生成/进化历史 |
| 表达与记忆（基底） | 任务层算子与基底真实参与执行且无副作用 | 技能 Top-K 命中率与采纳率；信封收窄率与**被隐藏工具实际调用率** | 分支覆盖率；记忆淘汰/保留条目的重要性分布（短但值钱的记录不被误删） | 路由历史+轨迹+记忆存储 |

**预期量级**（130 条、every-N=5、吸收上限 10、部署期每技能约 15 次执行）：约 26 个决策点；V0 进化关闭、零战役零产物；V3 预期吸收 6–10 个提交，以工具/提示层（通用机制）改动为主；技能生成量级为数十个（取决于门槛通过率和去重），其中被真实使用且成功率不足的进入变异；V3 总成本高于 V0，但每吸收提交成本应更低。以上只是量级估计，以实测为准。

### 4.3 进化期对比（四臂同图，图 4-1）

横轴 = 喂入语料的记录序 1–130，数据全部自动落盘：

- **(a) 累积吸收提交数**（主线 V3 vs V0；V1/V2 参考线）：V3 阶梯上升、V0 平线——"循环开没开"一眼可见；V1（没复盘）预期斜率和质量劣于 V3；V2（没技能）吸收线与 V3 接近，差异看 (b)(c)。
- **(b) 技能生命周期与前后测 Δ**（V3 vs V2 对照）：V3 的"生成→启用→部署→变异→回滚/覆盖"事件时间线 + 每技能基线→后测连线；V2 恒为零——遗传算子的产出差异直接可见。
- **(c) 决策质量与成本**（V1 的主观测）：**目标重复率**——同一改进目标（按目标文本归一化后的相似度判定）在进化后期被再次提出的比例——+ 每吸收提交成本。没复盘的 V1 预期重复率更高、单位收益更低：系统看得到"上一轮没成"，看不到"为什么没成"，于是换汤不换药地重提相似目标——这正是"反馈黑箱"缺口的直接量化。
- **(d) 机制运转核查**（零成本自动核查）：① 信用分离度——错误步骤和成功步骤的平均信用差（验证打分公式真让失败沉底）；② 评审链各闸门通过/拦截分布与就绪债务清偿记录（验证选择算子的保守语义）；③ **被隐藏工具的实际调用率**（应接近零——信封收窄不损失能力，3.2 的逃生通道几乎用不上）；④ 记忆淘汰/保留条目的重要性分布（验证"短但值钱"的记录不被误删）。

### 4.6 机制案例与产物画像（定性直证）

定量表格之外，用四个案例 + 一份画像直接看循环内部长什么样——材料全部来自自动落盘的文件，不需要任何额外实验：

1. **一次被拦截的候选**：挑一个没过评审链的战役候选，逐闸门回放否决过程（预审意见/越界文件/预检失败用例/审查结论），加对应的就绪债务登记与清偿。直观展示选择算子的保守语义——**进化的默认值是"不吸收"**，主线不会被未验证的修改污染。
2. **一次进化的自归因**：挑一次失败战役，展示 B 轨如何把失败定位到具体阶段（分析/构建/验证），以及失败模式如何进入下一次同类目标的战役上下文——"上一轮在验证阶段栽了，这一轮的验证清单被强化"。这是 LEAP 独有的性质：**进化不仅改进任务能力，也改进进化自己**。
3. **一个技能的一生**：完整走一遍生命周期——达标生成（附关键/拖累步骤）→ 审查启用 → 真实使用统计 → 触发重写（附注入的真实失败文本）→ 小测验+校准折扣 → 审查通过覆盖（或回滚恢复）→ 部署前后测 Δ。第 3.5 节的每个机制落到一条可追溯的时间线上。
4. **吸收提交的产物画像**：全部提交按修改层分布（工具层/提示层/流程层；通用机制 vs 任务特化），附 1–2 个代表提交的 diff 摘要和前后行为对比。预期以**通用机制层**为主——正是这类改动有资格跨域迁移，和 4.4 的 Terminal 收益互为印证。

## 5 结论

### 5.1 总结

本文提出 LEAP——一条以重要性记忆为账本、由表达、归因、定向变异、选择、遗传五个算子组成的完整自进化流水线，并在自进化编码智能体 Ouroboros 之上完成了从数据到评测的完整闭环。

方法上的推进是把问题从"智能体能不能改自己的代码"换成了"**这个修改循环能不能一直转下去**"：归因算子让每次成败都能定位到步骤（连进化自己的成败也能复盘）；定向变异让"改什么"有证据、有分工；选择算子用裁判分支+四级评审保证坏改不进主线，保守语义让"不吸收"成为默认值；遗传算子用提交和带谱系的技能把验证过的改进存下来；表达算子把存下的能力调度回任务。五个算子缺一不可——这正是四臂消融的设计依据。

实证上，进化期观测检验了循环能否持续产出、是否呈阶梯式累积；四臂消融直接检验了归因与遗传的必要性（对应黑箱与流失两个缺口的修复）；Terminal-Bench 主验收检验了跨域迁移收益；技能前后测直接度量传承收益；机制案例与产物画像给出定性直证。全部证据来自自动落盘的可审计文件。

### 5.2 局限与未来工作

- **单模型、单实例、单语料域**：实验基于单一模型家族、单一基础实例与 GAIA→Terminal-Bench 一条跨域链；更强/更弱的模型、其他实例基底、其他任务域（Web、科学计算）的普适性与移植成本有待验证。
- **手工校准的参数**：信用权重、生成门槛（≥8）、变异触发（≥10 次且 <80%）、适应度折扣都是人工按语料统计定的。3.2 的 L3（配置由轨迹统计生成）和 L4（结果回填自动调优）是既定路线——到时连路由参数也进化的对象。
- **进化安全的边界**：评审链和验证器依赖评审模型与测试的质量；评审弱于生成或测试覆盖不足时，自确认循环风险没有完全消除。下一步把评审链本身也纳入变异-选择循环（评审者也进化）。
- **成本与节奏**：every-N、战役并发度、迷你评估集大小目前是固定超参；"证据密度高时加密进化、稀疏时休眠"的自适应节奏值得探索。
- **有界的开放式进化**：本文的循环刻意运行在人类设定的目标与安全协议内（2.2 所说"有界、可验证"）；真正开放式的递归自改进仍是远景。

### 5.3 结语

自进化不是一次性改写自己的源码，而是一条算子完整、证据驱动、可传承的流水线。LEAP 的全部设计只为让这条流水线转下去：每一轮被验证的改进都以可回滚的提交和带谱系的技能固化下来，进化曲线因此是**阶梯而非平线**——**每一轮结束，都是下一轮的起点**。
